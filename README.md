# XL Blog

The Xmartlabs blog (https://blog.xmartlabs.com): a [Next.js 16](https://nextjs.org) site with [Payload CMS 3](https://payloadcms.com) built in, a Postgres database, and hosting on Vercel.

- Public site: `/`, `/page/<n>/`, `/categories/[<slug>/[page/<n>/]]`, `/blog/<slug>/`, `/authors/<slug>/`, `/tags/[<tag>/]`, `/sitemap-index.xml`.
- Admin panel (the CMS): `/admin`. Bloggers sign in with their @xmartlabs.com Google account.

## Where things live

| Path                           | What                                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `src/app/(frontend)/`          | Public pages (statically generated, revalidated on demand), sitemap route handlers, `/next/preview` (draft mode).                |
| `src/app/(payload)/`           | Payload admin panel and REST/GraphQL API (generated by Payload, don't edit).                                                     |
| `src/app/global-not-found.tsx` | 404 page for URLs that match no route.                                                                                           |
| `src/payload.config.ts`        | Payload config: database, storage, Google sign-in, jobs (scheduled publishing).                                                  |
| `src/collections/`             | `posts`, `authors`, `categories`, `media`, `users`.                                                                              |
| `src/blocks/`                  | Post body blocks: video, image/gallery, table, code, HTML embed.                                                                 |
| `src/components/rich-text/`    | Lexical → HTML renderer for post bodies (keeps the exact markup of the old site).                                                |
| `src/components/`              | React components of the site (nav menu, cards, post page, …).                                                                    |
| `src/lib/`                     | Data access (`posts.ts`, Payload Local API), SEO helpers, sitemap, revalidation hooks.                                           |
| `src/auth/`                    | Google sign-in (`payload-oauth2`), domain check, break-glass admin seed.                                                         |
| `src/migrations/`              | Database migrations (run on every Vercel build).                                                                                 |
| `public/`                      | Static files served at the site root. `public/images/…` holds every image of the old posts (`/images/foo.png`).                  |
| `scripts/migrate-content.ts`   | One-off import of the old Markdown blog into Payload (see "Content migration").                                                  |
| `migration/legacy/`            | Snapshot of the old site's rendered post bodies + metadata, the input of the import; also used for the old Jekyll URL redirects. |
| `blogs/`, `content/`           | The old Markdown posts, authors and categories (source of the snapshot; kept for reference).                                     |

## Local development

Requirements: Node 24.22.3+ (`.nvmrc`), Docker.

```sh
nvm use                      # Node 24.22.3
npm install
cp .env.example .env         # then fill in PAYLOAD_SECRET (openssl rand -hex 32) and DATABASE_URL
npm run db:up                # Postgres 17 in Docker (docker-compose.yml)
npm run dev                  # http://localhost:3000, admin at http://localhost:3000/admin
```

In development the database schema is pushed automatically from the Payload config (no migrations needed). To get the real content locally, run the content migration (below).

Other commands:

| Command                           | What                                                                    |
| --------------------------------- | ----------------------------------------------------------------------- |
| `npm run build` / `npm start`     | Production build (needs the database: pages are generated from it).     |
| `npm run ci`                      | `payload migrate` + `next build`. The Vercel build command.             |
| `npm test`                        | Unit tests (Vitest): Google domain check, rich-text renderer.           |
| `npm run typecheck`               | `tsc --noEmit`.                                                         |
| `npm run format` / `format:check` | Prettier.                                                               |
| `npm run generate:types`          | Regenerate `src/payload-types.ts` after changing collections or blocks. |
| `npm run generate:importmap`      | Regenerate the admin import map after adding admin components.          |

### Environment variables

See `.env.example` for the full list with comments.

| Variable                                    | Purpose                                                                                                                               |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                              | Postgres connection string. On Vercel the Neon integration sets it.                                                                   |
| `PAYLOAD_SECRET`                            | Signs auth tokens. Long random string, different per environment.                                                                     |
| `NEXT_PUBLIC_SERVER_URL`                    | Public URL without trailing slash, used for the Google OAuth redirect. On Vercel it falls back to the production domain / branch URL. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`  | Google OAuth client. Empty → no Google button (password login only).                                                                  |
| `GOOGLE_ALLOWED_DOMAIN`                     | `xmartlabs.com`. Only verified accounts of this Workspace domain can sign in.                                                         |
| `FIRST_ADMIN_EMAIL`, `FIRST_ADMIN_PASSWORD` | Break-glass admin, created on startup only while the users table is empty.                                                            |
| `BLOB_READ_WRITE_TOKEN`                     | Vercel Blob store for uploads. Empty → uploads go to `./media` on local disk.                                                         |
| `CRON_SECRET`                               | Lets Vercel Cron run the jobs queue (scheduled publishing). Letters/digits only.                                                      |
| `NEXT_PUBLIC_GTM_ID`                        | Google Tag Manager container. GTM is only added when set.                                                                             |
| `NEXT_PUBLIC_FORM_URL`                      | "Let's talk" form URL (iframe).                                                                                                       |
| `NEXT_PUBLIC_MEDIA_BASE_URL`                | Base URL for legacy self-hosted videos (video blocks with a legacy file name). Empty → `/images/`.                                    |

## Users and roles

- **Editors** (everyone by default): any @xmartlabs.com Google account gets an `editor` user on first sign-in. Editors can create, edit, publish and schedule posts, and add authors.
- **Admins**: everything editors can do, plus deleting posts/authors, managing categories, and promoting/demoting users (Users → open the user → Roles).
- **First admin**: set `FIRST_ADMIN_EMAIL`/`FIRST_ADMIN_PASSWORD` before the first start; it's created while there are no users and signs in with email + password. Use it to promote the first Google users to admin. Keep its password in the team vault; it's the break-glass account if Google sign-in breaks.

### Google sign-in setup (Google Cloud console)

1. Use a project of the xmartlabs.com Google Workspace organization.
2. **OAuth consent screen**: user type **Internal** (only accounts of the organization can sign in), app name "XL Blog", scopes `openid`, `email`, `profile`.
3. **Credentials → Create credentials → OAuth client ID**, type "Web application". Authorized redirect URIs:
   - `http://localhost:3000/api/users/oauth/google/callback`
   - `https://blog.xmartlabs.com/api/users/oauth/google/callback`
   - optionally one fixed preview host, e.g. `https://<branch alias>.vercel.app/api/users/oauth/google/callback`
4. Put the client id and secret in `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (locally in `.env`, on Vercel in the project's environment variables).

Google only redirects to registered URIs, so Google sign-in works on production, localhost and the registered preview host, **not on random per-deployment preview URLs**. On preview deployments `NEXT_PUBLIC_SERVER_URL` falls back to the branch URL (`VERCEL_BRANCH_URL`), which is stable per branch; register the one you use, or set `NEXT_PUBLIC_SERVER_URL` for the Preview environment to that host.

## Writing posts (bloggers)

1. Open https://blog.xmartlabs.com/admin and click **Sign in with Google**.
2. **Posts → Create new.** Fill in the title (12+ characters), category, author, 1–5 tags, thumbnail, and the body. The slug (URL `/blog/<slug>/`) is filled from the title; change it before publishing if needed.
3. Body: rich text plus blocks (`+` or `/` menu): **Image / gallery**, **Video** (YouTube URL or uploaded file), **Table**, **Code**, **HTML embed** (raw HTML, e.g. tweets or iframes; scripts in it are loaded once per page).
4. **Preview**: drafts autosave. The **Live Preview** tab shows the post next to the editor and updates as you type; **Preview** opens it in a new tab. Only signed-in users see drafts.
5. **Publish** makes it live within seconds (the affected pages are regenerated). **Unpublish** takes it down.
6. **Schedule**: next to Publish, choose **Schedule Publish** and pick a date/time. A cron job publishes due posts every 5 minutes.

Authors without an account are plain `authors` entries (name, slug, picture, profile URL); a user doesn't need to be an author and vice versa.

## Database migrations

Development uses schema push; production runs migrations on every deploy (`npm run ci` = `payload migrate && next build`).

When you change collections, fields or blocks:

```sh
npm run payload migrate:create <short-name>   # with the local DB up; writes src/migrations/<date>_<name>.ts
npm run generate:types                        # updates src/payload-types.ts
```

Review and commit the migration with the code. The next Vercel build applies it to the Neon database before building.

## Content migration (one-off)

```sh
npm run seed:migrate-content                                   # categories, authors, all 175 posts
MIGRATE_ONLY=vytallink-app,a-look-back-at-2020 npm run seed:migrate-content
npx payload run scripts/compare-bodies.ts                      # DB render vs migration/legacy/bodies: expect 175/175 exact
```

The import is idempotent (upsert by slug) and publishes posts with their original dates. It reads `migration/legacy/posts.json` and `migration/legacy/bodies/<slug>.html` (the verified rendering of the old site) and `content/{authors,categories}/*.yml`. To run it against production, point `DATABASE_URL` at the production database (after `payload migrate`).

## Deploy (Vercel)

`vercel.json` sets the framework, the build command `npm run ci`, and the scheduled-publishing cron (`/api/payload-jobs/run/` every 5 minutes; Vercel sends `Authorization: Bearer $CRON_SECRET`). Pages are statically generated at build time from the database and regenerated on demand when content changes (`src/lib/revalidate.ts`). See `MIGRATION-TODO.md` for the setup checklist.

## Rendering notes

- Post bodies are rendered from Lexical to one HTML string inside `.bodyPostContainer` (`src/components/rich-text/to-html.ts`), so the CSS that targets direct children (`.bodyPostContainer > p`, `> img`, …) matches the old markup exactly.
- SEO tags (`<title>`, combined `name`/`property` meta, canonical, Twitter card) are rendered by `src/components/seo/Seo.tsx` in each page and hoisted into `<head>` by React.
- Old Jekyll URLs (`/YYYY/MM/DD/<file name>/`) redirect to `/blog/<slug>/` (`next.config.mjs`).
