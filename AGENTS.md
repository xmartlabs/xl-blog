# AGENTS.md

Rules for AI agents and developers working on the Xmartlabs blog. `README.md` has the full setup, environment variables and deploy notes.

## Stack and commands

Next.js 16 (App Router) + Payload CMS 3 (Postgres, Lexical), npm, Node 24 (`nvm use`), Vercel + Neon.

```sh
npm run db:up          # local Postgres (Docker); dev DB `xlblog`
npm run dev            # http://localhost:3000, admin at /admin
npm run lint           # ESLint (next core-web-vitals + typescript, prettier-compatible)
npm run typecheck      # tsc --noEmit
npm test               # unit tests, no database (fast)
npm run test:int       # access-control tests on a real `xlblog_test` DB (needs db:up)
npm run test:e2e       # Playwright e2e on the production build (run `npm run build` first); own DB `xlblog_e2e`, port 3003
npm run format         # Prettier (format:check in CI)
npm run build          # needs the DB: pages are generated from it
npx payload run scripts/compare-bodies.ts   # must print 175/175
```

Before finishing a change, run lint, typecheck, `npm test`, and `npm run test:int` if it touches collections, access or auth. Don't modify the dev database's data from tests or scripts; integration tests use their own database (recreated each run).

## Where things live

- `src/payload.config.ts`: database, plugins, jobs, admin components, password-login switch.
- `src/collections/`: `posts`, `authors`, `categories`, `media`, `users`. Access helpers: `src/access/`.
- `src/auth/`: Google sign-in (`google.ts`), password-login switch, first-admin seed, login button.
- `src/lib/`: Local API data access (`posts.ts`), revalidation hooks, `redirects.ts` (`safeInternalPath`), cron auth.
- `src/components/rich-text/to-html.ts`: Lexical → HTML for post bodies.
- `src/app/(frontend)/`: public site and `/next/{preview,exit-preview,revalidate}`. `src/app/(payload)/`: generated by Payload, don't edit.
- `src/migrations/`: migrations (run on every deploy). `migration/legacy/`: verified snapshot of the old site, read-only.
- `tests/*.test.ts`: unit tests. `tests/int/*.int.spec.ts`: integration tests. `tests/e2e/*.spec.ts`: end-to-end tests (seed: `tests/e2e/seed.ts`). `tests/parity/`: comparison with the live site (not in CI).

## Payload rules

- **The Local API skips access control by default.** `payload.find/create/update/...` run with `overrideAccess: true` unless you pass `overrideAccess: false` *and* the `user`. Do that whenever an operation acts on behalf of a request's user (route handlers, endpoints). Integration tests must assert with `overrideAccess: false` + explicit `user` (`null` for anonymous).
- **Pass `req` to nested operations in hooks** (`payload.find({ ..., req })`) so they share the transaction and the user; without it they run in a separate transaction and can deadlock or see stale data.
- **Context flags** (`context: { ... }`): `disableRevalidate` skips on-demand revalidation (scripts, tests); `legacyImport` skips editorial validation (title length, tag count) and revalidation, for the content import only. Don't set `legacyImport` for new content.
- Access is defined once in the collection configs: editors create/update posts and authors; only admins delete, manage categories and users, and change `roles` or a user's `author` link (field access ignores those fields for editors). Editors can't change their own email or password (`Users` hook). Keep it that way unless asked, and cover changes in `tests/int/access.int.spec.ts`.
- **After changing collections, fields or blocks:** `npm run payload migrate:create <name>`, `npm run generate:types`, and `npm run generate:importmap` if admin components changed. Commit the migration, `src/payload-types.ts` and the import map with the code. CI fails if the schema and migrations differ. Dev uses schema push; production uses migrations only.
- GraphQL is disabled; the admin panel and the site use REST and the Local API.

## Public-rendering contract

The 175 imported posts must render byte-for-byte like the old site.

- `npx payload run scripts/compare-bodies.ts` must stay 175/175 (CI runs it after importing the content).
- Don't change `to-html.ts` output for legacy content (markup, attributes, whitespace). New behavior goes behind node types or options that imported posts don't use.
- The CSS targets the old markup (`.bodyPostContainer > p`, …); keep component markup stable unless the change is intended and checked in the browser.
- Old Jekyll URLs keep redirecting (`next.config.mjs`, `src/lib/legacy-redirects.mjs`).
- Unknown params in frontend pages: `return <NotFoundPage />`, not `notFound()` (Next 16 would send an empty error shell; see `src/components/not-found/NotFoundPage.tsx`).

## Google sign-in security rules

- **Fail closed.** No Google settings → no endpoints, no button. Anything unexpected in the callback → failure redirect, no user created.
- An identity is accepted only if `email_verified === true`, `hd` equals `GOOGLE_ALLOWED_DOMAIN` and the email ends with `@<domain>` (`checkGoogleIdentity`). The `hd=` authorize parameter is only a hint.
- The flow keeps a `state` (CSRF) and a PKCE verifier (S256) in short-lived HttpOnly cookies scoped to `/api/users/oauth/google`; the callback expires them. Don't remove either check.
- Return paths (`?redirect=`, `?path=`) always go through `safeInternalPath`. Never redirect to a URL taken from a request without it.
- New users are always `editor`; never derive roles or the author link from Google data.
- Never add relay, bypass, "login as" or token-minting endpoints, or alternative callback URLs.
- Password login is the break-glass admin only; `DISABLE_PASSWORD_LOGIN=true` turns it off once Google works.
- Never log or commit secrets (`.env`, tokens, client secrets).
